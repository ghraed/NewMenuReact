Real browser lifecycle:
  A guest enters the PIN returned by real assigned-staff activation, adds two
  USD 12.50 dishes and submits to the real API (201). Replaying the idempotency
  key returns the same order (200). Assigned staff confirms through the UI (200).
  A separate chef subscribes to the real private kitchen channel, starts preparation
  and marks ready through the UI (200 each). Assigned staff serves through real
  browser HTTP (200). With websocket held down, the kitchen's actual timed poll
  reconciles the served ticket. A separate authenticated admin uses the Accounting
  UI to finalize after USD 2.00 fixed discount and 10% VAT. Persisted paid invoice,
  rendered details, real generated PDF and finance agree on 25.00 - 2.00 + 2.30 =
  USD 25.30. Repeated finalization reuses one invoice; finance counts one invoice.
  PDF extracted text includes the real invoice number, item, VAT and total.

  event is published twice through Reverb and both frames arrive while one ticket

  persists one verified domain mapping and leaves zero pending/failed jobs. Its

  A real schedule:work daemon spawns guarded schedule:run and delivers the due
  T-1 reminder only. Repeated invocation keeps the same 12 role/channel logs;
  draft/future events have no logs. Push transport itself is disabled/excluded.
  Synthetic backup includes the owned schema and private/public disk tree. The
  latest real migration is rolled down/up; the paid invoice survives. The rehearsal
